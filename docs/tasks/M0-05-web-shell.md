# M0-05 · Оболочка web

## Цель

Сайт с каталогом игр и страницей `/play/:id`, которая лениво грузит модуль игры, монтирует её и полностью убирает при уходе со страницы.

## Что сделать

- [ ] `apps/web`: `Bun.serve` + HTML import + React 19. Все пути отдают SPA (fallback на `index.html`). Скрипт `dev` — `bun --hot`.
- [ ] Реестр игр `apps/web/src/games.ts`: `@repo/game-<game>/manifest` импортируется статически, `@repo/game-<game>/client` — через `() => import(...)`.
- [ ] Страница каталога: карточки из манифестов.
- [ ] Страница `/play/:id`: загрузка модуля, состояния загрузки и ошибки, 404 для неизвестного `id`, кнопка «Назад в каталог».
- [ ] Компонент `<GameHost>` монтирует игру в свой `div` и корректно обрабатывает гонку «unmount пришёл раньше, чем закончился mount».
- [ ] Роутинг на твой выбор: свой на History API (для двух страниц его достаточно) или TanStack Router. Объясни выбор в описании коммита.
- [ ] `ErrorBoundary` вокруг игры: если игра упала, падает только она, а не весь сайт.

## Критерии приёмки

- `React.StrictMode` включён, и в dev-режиме не появляется двух canvas или двух WebGL-контекстов.
- 20 переходов «каталог → игра → каталог» подряд: в консоли нет предупреждения Chrome «Too many active WebGL contexts», а в Memory → Heap snapshot не остаются висеть отсоединённые canvas.
- Продакшн-сборка (`bun build ... --splitting`): код Three.js попадает в отдельный чанк и не грузится на странице каталога (проверь во вкладке Network).

## Подсказки

- Для гонки в `<GameHost>`: сохраняй промис `mount` в эффекте; в cleanup делай `abort()` и вызывай `unmount`, когда промис зарезолвится. Не путайся с флагами `isMounted`: `AbortController` делает то же самое чище.
- Проверь, разбивает ли Bun бандл на чанки по динамическому импорту в dev-режиме HTML imports, или только в `bun build --splitting`. Для критерия приёмки важна продакшн-сборка, но знать поведение dev полезно.
- Пока заглушки `bridge` нет (это M0-06), для проверки подключи тестовую игру из пяти строк: canvas с WebGL-контекстом и cleanup.
