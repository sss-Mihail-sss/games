# M1-01 · Спайк Rapier

## Цель

Перед тем как строить на Rapier весь M1, ответить замерами на вопросы, от которых зависит архитектура физики:

1. **Какая сборка.** `@dimforge/rapier3d-deterministic-compat` или обычная `@dimforge/rapier3d-compat`. Даёт ли «детерминированная» сборка одинаковый результат в Chrome, Safari и под Bun на macOS и Linux? И, что не менее важно, не даёт ли того же обычная?
2. **Как грузится WASM.** Работает ли `await RAPIER.init()` в `bun test`, в Turbopack (`next dev` и `next build`) и внутри `mount` с отменой через `signal`? Сколько весит чанк игры и сколько длится инициализация?
3. **Сколько стоит шаг.** Сколько миллисекунд занимает `world.step()` при 50 досках и 100 соединениях — в Bun и в браузере?
4. **Снимки.** Работают ли `takeSnapshot()` / `restoreSnapshot()` так, как нужно для тестов и для отката в M2: восстановили и продолжили — получили то же, что без перерыва?
5. **Память.** Освобождается ли память WASM при `world.free()`, если создать и уничтожить мир 20 раз подряд?

**Спайк — это эксперимент, а не фича.** Код может быть черновым, но выводы — нет: каждая цифра в итоговой таблице должна быть воспроизводимой (команда, браузер, машина). Результат задачи — заполненный раздел «Результаты» в конце тикета и решения в ARCHITECTURE.md. По ним строится M1-02.

**Таймбокс: 2 дня.** Если какой-то вопрос не решается за это время, записываем «не выяснили, почему» и идём дальше с безопасным вариантом.

### 1. Сценарий: один и тот же мир везде

Нужна чистая функция, которая строит одинаковый мир и прогоняет его одинаковое число шагов в любой среде: в `bun test`, в браузере, в CI.

- [x] `games/bridge/src/sim/spike/scenario.ts`, без DOM и `three`. Функция принимает модуль Rapier (обе сборки имеют одинаковый API) и параметры, а возвращает результат:

  ```ts
  interface ScenarioResult {
    hash: string; // отпечаток итогового состояния
    stepMs: { mean: number; p95: number; max: number };
    snapshotBytes: number;
  }
  function runScenario(
    rapier: typeof RAPIER,
    options: { steps: number; dt: number },
  ): ScenarioResult;
  ```

- [x] Мир, похожий на будущую игру:
  - гравитация `(0, -9.81, 0)`;
  - два берега — неподвижные коллайдеры-кубы по размерам из `LEVEL`;
  - 50 досок 3 × 0,05 × 0,3 м (`ColliderDesc.cuboid` на динамическом теле). Часть стопкой на берегу, часть падает в провал с разной высоты и под разными углами. Позиции задавай формулой от индекса, никакого `Math.random`;
  - 100 соединений между соседними досками: `JointData.fixed` или `revolute`;
  - фиксированный `world.timestep = dt`.
- [x] **Отпечаток.** Для всех тел по порядку создания запиши `translation()` и `rotation()` как `Float64Array`, затем возьми хеш байтов. Под Bun — `Bun.hash`, в браузере — `crypto.subtle.digest("SHA-256", …)`. Но лучше один и тот же простой FNV-1a на TypeScript, чтобы сравнивались одинаковые числа. Почему не хеш `takeSnapshot()`: в снимок могут попадать служебные данные, которые различаются при одинаковой физике. Хеш позиций проверяет именно то, что важно игре.
- [x] Прогоны: 600 шагов при `dt = 1/30` (20 секунд игры) и 1200 при `dt = 1/60`, обеими сборками.

### Сборка без compat (шаг 6)

- **Turbopack:** собирается. WASM уходит отдельным файлом (3,1 МБ), в браузере работает, хеш тот же. Есть предупреждение сборки про трассировку путей в SSR-графе (`[turbopack-wasm]/node/loadWasm.ts`).
- **Bun:** не работает — `import * as wasm from "./rapier_wasm3d_bg.wasm"` не даёт инстанс WASM (`wasm.rawintegrationparameters_new is not a function`). Значит, в `sim`, который пойдёт на сервер, её не использовать.
- **Вывод:** теоретически возможно «в браузере без compat, на сервере compat» через условия в `imports` (`#physics`: `browser` → без compat, `default` → compat). Экономия ~600 КБ gzip и потоковая компиляция WASM. Откладываем до M1-08: два пакета вместо одного и предупреждение сборки сейчас не стоят выигрыша, пока нет замера «клик → первый кадр» с реальной игрой.

### Решения

- **Сборка:** `@dimforge/rapier3d-deterministic-compat` 0.21.0. Детерминизм подтверждён на macOS arm64, Linux x64 и в Chromium; по скорости и весу не хуже обычной — значит, гарантия бесплатна.
- **Загрузка WASM:** compat (WASM внутри JS, `await RAPIER.init()`), один пакет для браузера, `bun test` и сервера. Промис инициализации кешируется на страницу; при отмене после `await` игра ничего не создаёт. Сборка без compat — кандидат на M1-08.
- **Частота физики (предварительно):** тик протокола 30 Гц, физика — два подшага по `1/60` на тик. Стоимость: 2 × ~0,25 мс = ~0,5 мс на тик при 50 досках.
- **Снимки:** `takeSnapshot` / `restoreSnapshot` дают тот же хеш после отката и стоят доли миллисекунды — годятся для отката предсказания в M2 хоть каждый тик.
- **Память:** WASM-память сборщик мусора не освобождает. Каждый `World` — `free()` в unmount, это проверяет тест.
- **Что не выяснили:** Safari, Firefox и другие CPU; уход со страницы во время загрузки на медленной сети; «клик → первый кадр» с физикой. Первые два — ручная проверка до приёмки, третье — в M1-02.

## Подсказки

- **API у compat- и не-compat-сборок одинаковый,** отличается только загрузка. Пиши сценарий против типа модуля (`typeof import("@dimforge/rapier3d-compat")`) и передавай сам модуль параметром. Тогда одна функция работает с любой сборкой.
- **Rapier работает с WASM-памятью, а не с объектами JS.** `World`, `RigidBody` и `Collider` — это обёртки над указателями. Сборщик мусора их не освобождает: без `world.free()` память утекает навсегда. Векторы из `translation()` — свежие JS-объекты, их можно не освобождать.
- **`await` в `bun:test`.** Верхнеуровневый `await` в тест-файлах Bun поддерживает. Если он мешает, используй `beforeAll(async () => { await RAPIER.init(); })`.
- **Что такое «детерминизм» здесь.** Одинаковая версия Rapier + одинаковые входы + одинаковый порядок создания объектов → бит-в-бит одинаковый результат. Порядок создания важен: создай тела в другом порядке, и хеш другой. Это не баг, а условие, которое мы будем соблюдать в M2 на клиенте и сервере.
- **Не оптимизируй в спайке.** Цель — цифры и решения. Если шаг стоит 8 мс, запиши 8 мс. Оптимизировать будем в M1-08, когда увидим реальную сцену.
- **Сверяйся с документацией Rapier** по версии 0.21, а не по памяти: API между версиями заметно менялся (снимки, JointData, `timestep`).
