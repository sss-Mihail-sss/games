# M1-09 · Механики движения и способности

## Цель

Добавить аватару прыжок, спринт, присед и «крадучись» и сделать так, чтобы каждую механику можно было включить или выключить: по уровню игрока, по предметам, по персонажу или по правилам режима.

Как в M1-02 и M1-03, всё решает **`sim`**: решение 7 в `docs/tasks/README.md`. Клиент только отправляет нажатия и показывает результат. Если способность выключена, `sim` игнорирует действие. Это и есть защита: подменённый клиент в M2 не сможет «включить» себе спринт.

Параллельно закладываем две точки расширения на будущее:

- **характеристики персонажа** (M1-11) — множители к скоростям и высоте прыжка;
- **режим движения в `SimState`** — по нему анимации из M1-10 выберут бег, присед или прыжок.

## Что сделать

### 1. Действия и клавиши

- [ ] В `sim/actions.ts` добавь в **конец** списка: `jump`, `sprint`, `crouch`, `sneak`. Порядок битов — это протокол, поэтому существующие четыре бита не двигаются.
- [ ] Клавиши по умолчанию в клиенте:
  - `jump` — `Space`;
  - `sprint` — `ShiftLeft`;
  - `crouch` — `KeyC`;
  - `sneak` — `KeyZ`.
- [ ] **Не используй `Ctrl` и `Alt`.** `Ctrl+W` закрывает вкладку, и `preventDefault` это не отменяет; `Alt` в Windows уводит фокус в меню окна. Переназначение клавиш появится в M1-12.
- [ ] Прыжок срабатывает по биту **`pressed`** — это событие, а не состояние. Спринт, присед и «крадучись» — по **`held`**: держишь — действует.

### 2. Параметры движения — данными

- [ ] В `sim/movement.ts` базовые параметры:

  ```ts
  export const MOVEMENT = {
    walkSpeed: 4,
    sprintSpeed: 6.5,
    crouchSpeed: 2,
    sneakSpeed: 1.5,
    jumpHeight: 1.1, // м; скорость отрыва — √(2·g·h)
    coyoteTicks: 3, // ~100 мс: прыжок ещё можно после схода с края
    jumpBufferTicks: 3, // нажал чуть раньше приземления — прыжок сработает
    crouchHeight: 1.1, // общая высота капсулы в приседе
  } as const;
  ```

- [ ] **Характеристики** (`MovementStats`) — множители к этим числам: `{ speed, sprint, jump }`, по умолчанию все `1`. Персонаж из M1-11 передаст свои, например `speed: 1.1, jump: 0.9`. Баланс правится в одном месте, у базовых чисел.
- [ ] `WALK_SPEED` из M1-02 заменяется на `MOVEMENT.walkSpeed`. Тесты M1-02 на скорость ходьбы не меняются, только константа.

### 3. Способности

- [ ] `Abilities = { jump: boolean; sprint: boolean; crouch: boolean; sneak: boolean }`.
- [ ] `createSim(R, options)` с опциями:
  - `abilities` — по умолчанию всё включено;
  - `stats` — по умолчанию множители `1`;
  - `level` — функция, строящая уровень. По умолчанию `buildLevel`. Нужна тестам, чтобы поставить низкую балку над аватаром (шаг 6).
- [ ] **Выключенная способность:** соответствующий бит в кадре `sim` просто не замечает, как если бы клавишу не нажимали.
- [ ] `sim.setAbilities(next)` — **изменение внутри матча.** Вызывать только на границе тиков. В M2 это будет событие от сервера с номером тика, которое клиент и сервер применяют одинаково. До M5 и предметов вызывают его только тесты, но API нужен сейчас, чтобы снимки и детерминизм были рассчитаны на изменение способностей.
- [ ] `abilities` — в `SimState` (клиенту для подсказок) и в `SimSnapshot` (иначе откат в M2 разойдётся).

### 4. Режимы движения

Каждый тик `sim` выбирает один режим, по приоритету:

1. **В воздухе** (`!grounded`) — `air`. Горизонтальная скорость — та, с которой оторвался от земли. Направление можно чуть корректировать (например, 30 % от наземного). Начать спринт в воздухе нельзя.
2. **Присед** (держит `crouch` и способность есть) — `crouch`, `crouchSpeed`.
3. **Крадучись** — `sneak`, `sneakSpeed`, и **с края не падаешь** (шаг 7).
4. **Спринт** (держит `sprint`, движется и способность есть) — `sprint`, `sprintSpeed`.
5. Иначе — `walk`.

- [ ] `SimState.avatar` получает:
  - `mode: "walk" | "sprint" | "crouch" | "sneak" | "air"`;
  - `crouched: boolean`;
  - `speed` — горизонтальная скорость за тик, м/с. По ней M1-10 выберет анимацию.
- [ ] Скорость умножается на `stats.speed`, спринт — ещё и на `stats.sprint`.

### 5. Прыжок

- [ ] Условие: способность `jump` есть, и (аватар на земле **или** был на земле не больше `coyoteTicks` назад), и нажатие было не раньше `jumpBufferTicks` назад. Тогда `vy = √(2·|g|·jumpHeight·stats.jump)`, а «последнее нажатие» и «последняя земля» сбрасываются, чтобы не прыгнуть дважды.
- [ ] Счётчики «тиков с последней земли» и «тиков с последнего нажатия» — в состоянии `sim` и в снимке.
- [ ] Прыжок из приседа: аватар сначала встаёт и прыгает, только если над головой есть место (шаг 6). Иначе прыжок не происходит.
- [ ] Повторный прыжок в воздухе невозможен. Двойной прыжок — будущая способность персонажа, не в этой задаче.

### 6. Присед

- [ ] **В приседе меняется коллайдер, а не только картинка:**
  - `collider.setHalfHeight(...)` до высоты `crouchHeight`;
  - `collider.setTranslationWrtParent(...)` — новое положение центра капсулы над ногами;
  - под низкую балку теперь можно пролезть.
- [ ] **Встать можно, только если есть место.** Перед вставанием проверь, что капсула полной высоты в этой позиции ни с чем не пересекается: `world.intersectionsWithShape(..., excludeCollider: свой)`. Нет места — остаётся в приседе, даже если `crouch` отпущен.
- [ ] Точка прицела (`aimRay` из M1-03) в приседе ниже: высота плеча пропорциональна высоте капсулы. Камера опустится вместе с ней сама: она стоит на том же луче.
- [ ] `crouched` — в снимке. Форма коллайдера сохраняется в снимке Rapier, но проверь это тестом: после отката присед должен остаться приседом.

### 7. «Крадучись»: с края не падаешь

- [ ] Перед подшагом движения проверь, есть ли земля под **новой** позицией: луч вниз от неё на ~0,5 м, без своей капсулы. Нет земли — горизонтальное движение этого подшага не применяется.
- [ ] Лучше, чем просто остановка: проверь по осям отдельно и оставь ту составляющую, которая не ведёт с края. Тогда вдоль края провала можно идти, а шагнуть в него нельзя.
- [ ] Только в режиме `sneak`. В `walk` и `sprint` с края падаешь, как сейчас.

### 8. Клиент

- [ ] Клавиши из шага 1. Режимы и прыжок визуально — временно: капсула в приседе ниже (масштаб по Y), в прыжке просто летит. Анимации — в M1-10.
- [ ] Подсказка при попытке использовать выключенную способность: например, «Спринт недоступен» на секунду. Клиент знает и о нажатии, и о `state.abilities`. **Решение принимает `sim`**, подсказка — только картинка.
- [ ] Оверлей M1-03 дополни строкой про новые клавиши.

### 9. Тесты

- [ ] **Режимы:**
  - спринт быстрее ходьбы ровно в `sprintSpeed / walkSpeed` раз;
  - присед и «крадучись» медленнее;
  - `stats.speed: 1.5` даёт ×1,5.
- [ ] **Прыжок:**
  - высота подъёма ≈ `jumpHeight` (±2 см) — ищи максимум `y` за прыжок;
  - не прыгает в воздухе;
  - «время койота»: сошёл с края — 2 тика спустя прыжок есть, 5 тиков спустя нет;
  - буфер: нажал за 2 тика до приземления — прыжок, за 5 — нет;
  - `stats.jump` меняет высоту.
- [ ] **Присед:**
  - под балкой высотой 1,4 м (через опцию `level`) стоя пройти нельзя, в приседе можно;
  - под балкой нельзя встать, даже отпустив `crouch`; вышел из-под неё — встал.
- [ ] **«Крадучись»:**
  - к провалу — останавливается у края, `respawns` не растёт;
  - вдоль края — идёт;
  - `walk` к тому же краю — падает.
- [ ] **Способности:**
  - выключенный `jump` — нажатие ничего не делает, и так для каждой;
  - `setAbilities` посреди сессии работает со следующего тика.
- [ ] **Детерминизм:**
  - новая золотая сессия с прыжками, приседом, спринтом и «крадучись» у края. Константа меняется, объясни в PR;
  - снимок во время прыжка (в воздухе) и в приседе под балкой: после отката тот же результат.
- [ ] Старые тесты M1-02 и M1-03 зелёные: ходьба, падение, прицел.

## Критерии приёмки

- **Ощущения:**
  - прыжок отзывчивый: срабатывает и сразу после схода с края, и при нажатии чуть раньше приземления;
  - спринт заметно быстрее;
  - в приседе камера и капсула ниже;
  - «крадучись» вдоль края провала не роняет вниз.
- **Защита:** выключи `sprint` и `jump` в опциях `createSim` (временно в клиенте) — клавиши ничего не делают, появляется подсказка.
- **Тесты:** все из шага 9 зелёные, новая золотая сессия совпадает в CI на Linux.
- **Без регрессий:** ходьба, падение, респаун, прицел и камера из M1-02 и M1-03 работают как раньше.
- `bun run typecheck`, `bun run test`, `bun lint --max-warnings=0`, `bun fmt --check`, CI зелёный.

## Подсказки

- **Буфер и «время койота» — счётчики тиков, а не таймеры.** `sim` не знает времени, только тики. Это и даёт детерминизм.
- **`pressed` копится между тиками в `createInput`:** короткое нажатие Space между двумя тиками не потеряется, оно попадёт в ближайший кадр.
- **Высота прыжка из скорости:** `v = √(2·g·h)`. Но гравитация считается по подшагам (`vy += g·dt`), а это дискретная схема, поэтому реальная высота чуть меньше расчётной. Поэтому в тесте допуск, а если не попадает — поправь формулу на дискретность (или подбери `jumpHeight` по замеру).
- **`setHalfHeight` у капсулы задаёт половину цилиндрической части**, как `ColliderDesc.capsule` в M1-02, а не половину всей высоты.
- **После смены формы коллайдера** контроллер в том же подшаге видит старую форму, пока не пройдёт `world.step()`. Меняй форму в начале тика, до подшагов.
- **Проверка «есть ли место встать»** — на месте ног, с той же формой, что получится после вставания, и с `excludeCollider` своего коллайдера. Иначе капсула «пересечётся сама с собой».
- **Не добавляй прыжок и присед в `walkDirection`:** это функции разных уровней. Пусть `walkDirection` остаётся про направление, а режим и скорость выбирает отдельная чистая функция, например `movementMode(...)`. Её удобно тестировать без Rapier.
