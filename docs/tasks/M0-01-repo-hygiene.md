# M0-01 · Гигиена репозитория

## Цель

Монорепо, в котором с чистого клона работают `bun install`, `bun check` и `bun test`. У всех пакетов единые имена и общий базовый tsconfig.

## Контекст

Сейчас `git` не инициализирован, пакеты созданы через `bun init` (у каждого своя копия tsconfig и README из шаблона), а в корневом tsconfig нет DOM-типов. Лишний `bun.lock` в `packages/ui` и дублирующиеся `CLAUDE.md` я уже удалил.

## Что сделать

- [ ] `git init`, первый коммит с текущим состоянием репозитория в ветку `main`. От этого коммита начнётся ревью.
- [ ] Имена пакетов: библиотеки — `@repo/<name>` (`@repo/game-core`, `@repo/ui`, `@repo/game-bridge` и т. д.), приложения — `web`, `api`, `game-server` (на эти имена ссылаются корневые скрипты).
- [ ] Workspaces: `["apps/*", "packages/*", "games/*"]`. Удалить пустую `packages/games/`.
- [ ] Связи между пакетами только через `"workspace:*"`.
- [ ] `exports` у библиотек указывает прямо на TS-исходники, без шага сборки: `"exports": { ".": "./src/index.ts" }`.
- [ ] `tsconfig.base.json` в корне, пакеты делают `extends`. Удалить скопированные tsconfig'и из шаблона.
- [ ] DOM-типы (`"lib": ["ESNext", "DOM", "DOM.Iterable"]`) только у клиентских пакетов. Пакеты, которые работают на сервере (`game-protocol`, `contracts`, `db`, `auth`, `apps/api`, `apps/game-server`), DOM видеть не должны.
- [ ] Корневые скрипты: `dev`, `typecheck` (`bun check`), `test` (`bun test`). Скрипт `dev` не должен падать из-за пакетов без своего `dev`.
- [ ] Корневой README: что это за проект, как запустить, ссылка на `docs/`. Шаблонные README из пакетов удалить или переписать.
- [ ] Решить судьбу `@ui-sdk/core` и `@ui-sdk/react` в `packages/ui`: это бета-пакеты, и я их не знаю. Либо обоснуй выбор в README пакета, либо убери.
- [ ] `.gitignore`: `node_modules`, `dist`, `.env*` (кроме `.env.example`), `.DS_Store`. Решить, что делать с `.idea/`.

## Критерии приёмки

- `rm -rf node_modules **/node_modules && bun install && bun check && bun test` проходит. Пока тестов нет, `bun test` может ничего не найти, но не должен падать.
- Во всём репо один `bun.lock`, в корне.
- Если импортировать `document` в `packages/contracts`, `bun check` выдаёт ошибку.

## Подсказки

- Правило «серверный код не видит DOM» — самая дешёвая защита от того, что `sim/` случайно потянет браузерные API и перестанет запускаться на сервере. Для пакетов игр, где в одном пакете лежат и `sim/`, и `client/`, мы вернёмся к этому в M1: там понадобятся отдельные tsconfig на подпапки или отдельные пакеты.
- Проверь, как `bun check` ведёт себя в монорепо: проверяет ли он из корня все пакеты с их tsconfig'ами, или нужен `bun run --filter '*' typecheck`. Выбери вариант, при котором `bun run typecheck` в корне ловит ошибки во всех пакетах.
