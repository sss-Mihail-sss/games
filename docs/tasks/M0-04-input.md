# M0-04 · Ввод

## Цель

Игра работает с абстрактными действиями (`moveForward`, `grab`, `nail`…), а не с клавишами. Ввод снимается **по тикам**, а не по кадрам. Снимок ввода за тик (`InputFrame`) сериализуем: в M2 он полетит на сервер.

## Что сделать

- [ ] `createInput({ bindings, target? })`: `bindings` — карта «действие → список клавиш», `target` — по умолчанию `window`.
- [ ] `sample(tick): InputFrame` — вызывается раз в тик из `update`. Возвращает зажатые действия, а также нажатые и отпущенные с прошлого `sample`.
- [ ] `InputFrame` компактный и сериализуемый: битовая маска действий плюс номер тика. Добавь `encode` и `decode` в `Uint8Array` с тестом на круговую конвертацию.
- [ ] `setBindings()` — переназначение клавиш на лету.
- [ ] `dispose()` снимает все слушатели.
- [ ] Тесты: события подаются через обычный `EventTarget` и `Event` с полем `code`, без браузера.

## Критерии приёмки

- Клавиши определяются по `KeyboardEvent.code`, а не по `key`. С русской раскладкой WASD работает так же, как с английской.
- Короткое нажатие между двумя тиками не теряется: если клавишу нажали и отпустили внутри одного тика, `justPressed` всё равно сработает в ближайшем `sample`. Это проверено тестом.
- При `blur` окна все зажатые клавиши сбрасываются (иначе аватар «залипает» после Alt+Tab). Проверено тестом.
- Автоповтор (`event.repeat`) не порождает повторных `justPressed`.

## Подсказки

- Главная ловушка — делать `justPressed` по кадрам рендера. При 144 Гц мониторе и 30 Гц симуляции нажатие может «проскочить» между тиками или сработать несколько раз. Поэтому снимаем по тикам.
- Сейчас делаем только клавиатуру. Мышь и геймпад добавим позже, когда понадобятся. Но спроектируй `bindings` так, чтобы это не потребовало ломать API: например, `"Key:KeyW"`, `"Mouse:0"`, `"Pad:0"`.
- Ограничь число действий 32 битами маски, этого нам хватит надолго.
