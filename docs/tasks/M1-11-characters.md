# M1-11 · Персонажи

## Цель

Игрок выбирает персонажа в главном меню. У каждого персонажа своя модель и свои характеристики: один быстрее, другой прыгает выше. Выбор запоминается для игры отдельно. Некоторые персонажи могут быть закрыты: в M1 это пример с надписью «Откроется позже», в M5 доступность придёт с сервера по аккаунту.

Почти всё для этого уже есть:

- **характеристики** — `MovementStats` из M1-09: множители к скоростям и прыжку, которые принимает `createSim(R, { stats })`;
- **модели** — пайплайн и реестр `AVATAR_MODELS` из M1-10, плюс генератор `assets/models/builder.ts`;
- **запоминание** — хранилище игры из M1-12;
- **место в меню** — между «Играть» и «Настройки» (M1-12 оставил его специально).

## Уточнение решения 9: кто рисует экран выбора

В решении 9 записано: «экран выбора — в игре, а не в оболочке». Но в M1-12 мы договорились, что **меню рисует платформа**: один React-каркас, фокус с клавиатуры, стиль сайта, а в игре нет ни React, ни своих кнопок. Экран выбора — такое же меню, и делать его в игре значило бы писать второй UI-кит на чистом DOM.

Поэтому делим так:

- **платформа рисует панель выбора** — список, характеристики, замки, кнопки «Выбрать» и «Назад». Это общий компонент для любой игры с персонажами;
- **игра показывает 3D-превью** — за меню и так виден кадр игры. Наведи на персонажа в списке, и игра поставит его модель на место аватара и повернёт камеру к нему лицом;
- **данные — игры:** список персонажей, их характеристики и подписи к ним игра отдаёт так же, как `controls` в M1-12. Каталог о персонажах по-прежнему ничего не знает.

Решение 9 в README обнови этим текстом (шаг 10).

## Что сделать

### Часть A · Данные: `sim` и модели

#### 1. Персонажи в `sim`

- [ ] `games/bridge/src/sim/characters.ts`, чистые данные без Rapier и `three`:

  ```ts
  export interface Character {
    readonly stats: MovementStats; // множители из M1-09
    readonly abilities?: Partial<Abilities>; // см. ниже
  }

  export const CHARACTERS = {
    builder: { stats: { speed: 1, sprint: 1, jump: 1 } },
    runner: { stats: { speed: 1.12, sprint: 1.08, jump: 0.9 } },
    rigger: { stats: { speed: 0.92, sprint: 1, jump: 1.2 } },
    welder: { stats: { speed: 1, sprint: 0.95, jump: 1.05 } }, // закрыт в M1, шаг 5
  } as const satisfies Record<string, Character>;
  export type CharacterId = keyof typeof CHARACTERS;
  export const DEFAULT_CHARACTER: CharacterId = "builder";
  ```

  Имена и описания — не в `sim`: это тексты интерфейса, они живут в клиенте (шаг 4). В `sim` только то, что влияет на физику.

- [ ] `createSim(R, { character })` вместо `stats`: `sim` сам берёт `CHARACTERS[character].stats`. Неизвестный `id` — исключение. В M2 сервер получит `id` из лобби, и подменить характеристики клиентом нельзя: клиент передаёт только `id`.
- [ ] **Поле `abilities` персонажа может давать и отнимать способности** (`abilities?: Partial<Abilities>`). Сейчас никто ими не пользуется, но тип нужен: решение 9 говорит «характеристики и способности, которые даёт персонаж». Итоговые способности = способности уровня (`options.abilities`) **и** персонажа: отнять может любой, дать — только если разрешает уровень.
- [ ] **Сила** (сколько досок несёшь, как быстро забиваешь гвоздь) появится в M1-04 вместе с досками. Не добавляй её сейчас: поле, которое ничего не делает, нечем проверить.
- [ ] `builder` — со всеми множителями `1`. Тогда золотой хеш из M1-09 **не меняется**, и это проверка, что ничего не сломалось.

#### 2. Модели персонажей

- [ ] Генератор `assets/models/builder.ts` → общий `figure.ts` с параметрами:
  - палитра (`COLORS`);
  - головной убор (каска, кепка, бандана);
  - ширина плеч или телосложение — **без изменения длины ног и роста**.
- [ ] Скрипты `model:builder`, `model:runner`, `model:rigger` (или один `models`, который пишет все). Затем `bun run assets` как в M1-10.
- [ ] `AVATAR_MODELS` получает `runner` и `rigger`. Закрытому `welder` своя модель пока не нужна: `builder` подойдёт.
- [ ] В клиенте — `CHARACTER_MODELS: Record<CharacterId, AvatarModelId>`. Тип сам не даст забыть модель для нового персонажа.
- [ ] **Почему рост и ноги одинаковые:**
  - капсула в `sim` у всех одна (`AVATAR_HEIGHT`), и модель другого роста проваливалась бы в землю или парила над ней;
  - шаги в клипах рассчитаны на длину ног (`GAIT_SPEEDS`, M1-10): с другими ногами ступни скользили бы по земле.

  Разный размер капсулы — отдельная задача на будущее, если понадобится.

- [ ] Каждая модель проходит тесты M1-10: соглашения решения 8, все клипы из `AVATAR_ANIMATIONS`, размер файла.

#### 3. Тесты части A

- [ ] `runner` за секунду ходьбы проходит в 1,12 раза больше `builder` (как тест `stats.speed` в M1-09, но через `character`).
- [ ] `rigger` прыгает выше: пик ≈ `jumpHeight · 1,2` (±2 см).
- [ ] Неизвестный `character` — исключение.
- [ ] Способность, отнятая персонажем, не работает, даже если уровень её разрешает. Если уровень её отнял, персонаж её не вернёт.
- [ ] Данные персонажей в разумных пределах: каждый множитель `0,5…1,5`. Защита от опечатки `11.2` вместо `1.12`.
- [ ] Золотой хеш сессии не изменился.

### Часть B · Контракт и платформа

#### 4. Персонажи в контракте игры

- [ ] В `@repo/game-core`, по образцу `Controls`:

  ```ts
  export interface CharacterOption {
    id: string;
    name: string;
    description?: string;
    /** Для полосок на панели: подпись и множитель, 1 — как у базового. */
    stats: readonly { label: string; value: number }[];
    /** Закрыт, и почему: «Откроется позже». Решает платформа, см. шаг 5. */
    lock?: string;
  }

  export interface Characters {
    list: readonly CharacterOption[];
    default: string;
  }
  ```

  `defineGame({ manifest, controls, characters, mount })` и `GameModule.characters?`.

- [ ] Bridge собирает `characters` из `CHARACTERS` и своих подписей:
  - имена — «Строитель», «Бегун», «Монтажник», «Сварщик»;
  - описания — одна фраза;
  - характеристики — «Скорость», «Бег», «Прыжок» из множителей.

  Подписи — в клиенте, рядом с `CONTROLS`.

- [ ] `GameContext.character`:

  ```ts
  character: {
    /** Выбранный персонаж: с ним начнётся следующая игра. */
    readonly selected: string;
    /** На кого игрок смотрит в списке, или null: показать его вместо выбранного. */
    readonly preview: string | null;
    subscribe(listener: () => void): () => void;
  }
  ```

  Игра только читает. Выбирает игрок на панели платформы.

#### 5. Хранилище выбора и доступность

- [ ] `createCharacterStore(storage, gameId, characters, isAvailable)` в платформе, по образцу `createBindingsStore`:
  - ключ `games:<id>:character`;
  - при загрузке: неизвестный или закрытый `id` → `characters.default`. Граница доверия, как всегда: в `localStorage` можно записать что угодно;
  - `select(id)` сохраняет и уведомляет, но только доступного персонажа. Для закрытого — `false` без изменений;
  - `setPreview(id | null)` — не сохраняется.
- [ ] **Доступность решает платформа, а не игра:** `isAvailable(option)`. В M1 — «всё, у чего нет `lock`». В M5 здесь будет ответ сервера по аккаунту, а игра не изменится.
- [ ] Чтобы было что проверить, у «Сварщика» (`welder`) `lock: "Откроется позже"`. Остальные три открыты.
- [ ] Тесты:
  - пустое хранилище → `default`;
  - мусор, неизвестный и закрытый `id` → `default`;
  - `select` закрытого → `false`, ничего не сохранено;
  - `select` открытого → сохранено, подписчик уведомлён, переживает перезагрузку;
  - `setPreview` не пишет в хранилище.

#### 6. Панель «Персонаж» в главном меню

- [ ] В главном меню между «Играть» и «Настройки» — кнопка «Персонаж: Строитель», если у игры есть `characters`.
- [ ] Панель выбора (`apps/web/src/game-shell`):
  - **список слева** — пусть модель в центре кадра остаётся видна;
  - **у каждого персонажа:** имя, описание и полоски характеристик с подписью в процентах относительно базового («Скорость +12 %», «Прыжок −10 %»);
  - **закрытый** — с замком и причиной, выбрать нельзя, но посмотреть превью можно;
  - **клавиатура:** стрелки двигают по списку, Enter выбирает, Esc — «Назад»;
  - **кнопки:** «Выбрать» и «Назад».
- [ ] **Превью:** фокус или наведение на персонажа → `setPreview(id)`. «Назад» и закрытие панели → `setPreview(null)`.
- [ ] **Только в главном меню.** В меню паузы персонажа не меняем: он часть мира, и смена посреди игры означала бы новую игру. Это решение 9: «выбранный персонаж — часть настройки мира».

### Часть C · Bridge

#### 7. Новый персонаж — новый мир

- [ ] `menu → playing` (из M1-12 B):
  - если выбранный персонаж **совпадает** с тем, с которым создан мир, — как сейчас, `sim.restore(initial)`;
  - если **другой** — `sim.dispose()`, затем `createSim(R, { character })`, новый `initial`.
- [ ] Модель аватара меняется вместе с персонажем.
- [ ] Почему не `setStats` посреди мира: характеристики — часть настройки мира, их нет в снимке. А пересоздать мир дёшево, это миллисекунды.
- [ ] После 20 смен персонажа память Rapier не растёт: проверь dev-логом из M1-02 (`physics memory … MB`).

#### 8. Превью в меню

- [ ] Пока открыто меню: показывается `preview ?? selected`. Модель меняется без пересоздания мира: превью — только картинка.
- [ ] **Загрузка моделей:**
  - по требованию, с кешем по `id`. Повторное наведение не грузит файл снова;
  - пока модель грузится, остаётся предыдущая;
  - все загруженные модели освобождаются в `unmount` (проверка GPU-памяти из M1-02 должна показать `geometries → 0`).
- [ ] **Камера в меню смотрит на персонажа спереди:** сейчас она за плечом и показывает спину. Например, точка в 3 м перед аватаром на высоте груди. Модель медленно поворачивается, или игрок крутит её мышью — на твой выбор.
- [ ] **Пока цикл стоит** (меню), превью рисует кадры само: модель вращается и анимация `idle` играет. Это отдельный `requestAnimationFrame` только на время превью, `sim` в нём не шагает. Закрыл панель — rAF остановлен, снова один кадр по требованию (M1-12 B, `redraw`).
- [ ] Учитывай `reducedMotion`: без вращения.

## Критерии приёмки

- **Выбор:**
  - в главном меню видно «Персонаж: Строитель»;
  - в списке четыре персонажа, «Сварщик» закрыт;
  - при движении по списку модель за меню меняется, камера смотрит в лицо;
  - «Выбрать» → кнопка в меню показывает нового персонажа;
  - после перезагрузки выбор сохранён.
- **Игра:**
  - «Бегун» заметно быстрее, «Монтажник» прыгает выше: на уступ, на который «Строитель» не запрыгивает;
  - смена персонажа в меню → «Играть» → новый мир с новым персонажем.
- **Закрытый:**
  - выбрать нельзя, причина видна;
  - подмена `games:bridge:character` в `localStorage` на закрытого или выдуманного → после перезагрузки «Строитель».
- **Ресурсы:**
  - 20 переходов по списку и 20 смен персонажа без роста памяти Rapier;
  - `geometries → 0` после ухода со страницы.
- **Без регрессий:**
  - движение, прыжок, присед, камера, пауза, настройки;
  - золотой хеш M1-09 тот же.
- `bun run typecheck`, `bun run test`, `bun lint --max-warnings=0`, `bun fmt --check`, CI зелёный.

## Подсказки

- **Множители, а не числа** (решение 9): `runner.stats.speed = 1.12`, а не `walkSpeed: 4.48`. Поменял `MOVEMENT.walkSpeed` — изменились все персонажи сразу, баланс в одном месте.
- **Персонаж передаётся как `id`, а не как характеристики.** В M2 клиент пришлёт серверу «я `runner`», сервер проверит доступность и сам возьмёт `CHARACTERS.runner`. Если бы клиент присылал `{ speed: 1.12 }`, ему бы ничего не стоило прислать `{ speed: 5 }`.
- **Имена и описания — в клиенте, а не в `sim`.** Это тексты интерфейса: они переедут в переводы, а `sim` от языка не зависит. В `sim` только числа, влияющие на физику.
- **Превью — не новый мир.** Пока игрок листает список, меняется только модель в сцене. Мир пересоздаётся один раз — по «Играть» с другим персонажем.
- **Один кадр по требованию уже есть** (`redraw` из M1-12 B). Для вращения превью нужен свой короткий rAF-цикл: заведи его на время открытой панели и не забудь остановить в `unmount`.
- **Клон, а не та же модель:** `createAvatar(model)` из M1-10 уже клонирует сцену через `SkeletonUtils.clone`. Освобождай `Avatar` при смене, а `AvatarModel` — только в `unmount`: клоны делят геометрию и текстуры модели.
- **Скачивать чужие модели не нужно.** Варианты делает наш генератор. Если всё же захочешь CC0-модель, сначала спроси: имя файла, источник, лицензия, размер (как в M1-10).
