# M1-02 · Физический мир в `sim`

## Цель

Перевести `sim` с «ручной» математики M0-06 на Rapier. По сути аватар ведёт себя так же: ходит на WASD относительно камеры. Но теперь он стоит на настоящих коллайдерах берегов, а если шагнуть в провал или с края — падает, и через секунду-другую появляется на точке старта.

Важна не только сама физика, но и форма `sim`, на которой будет стоять весь M1 и сервер в M2:

- **Мир Rapier изменяемый**, поэтому чистая функция `step(state) → state` уступает место объекту с методом `step(frame)`.
- **Снимки** `snapshot()` / `restore()` заменяют неизменяемость: по ним мы тестируем детерминизм, а в M2 будем откатывать предсказание.
- **Рендер по-прежнему получает простые числа** (`SimState`) и интерполирует между двумя последними тиками.

Решения из спайка [M1-01](M1-01-rapier-spike.md): сборка `@dimforge/rapier3d-deterministic-compat`, WASM внутри JS, тик 30 Гц и два подшага физики по `1/60`.

## Что сделать

### 1. Загрузка физики — одна на всех

- [ ] `sim/physics.ts`: `loadPhysics(): Promise<Rapier>` — один `RAPIER.init()` на процесс или страницу. Промис кешируется, при ошибке забывается, и следующий вызов повторяет загрузку. Код почти такой же, как временный `client/physics.ts` из спайка, но живёт в `sim`: его будут вызывать и клиент, и тесты, и сервер в M2.
- [ ] `export type Rapier = typeof RAPIER` переезжает сюда из `sim/spike/scenario.ts`, а сценарий импортирует тип из `physics.ts`.

### 2. Уровень: коллайдеры из `LEVEL`

- [ ] `sim/level.ts`: `buildLevel(world, R)` создаёт неподвижные коллайдеры двух берегов по `LEVEL`: верх на `y = 0`, внутренние края на `±gap/2`. Клиентская сцена уже строит геометрию из тех же чисел, поэтому стены физики совпадут с картинкой.
- [ ] Воды в физике нет: это картинка. В провал аватар падает свободно.

### 3. Аватар на character controller

- [ ] Тело `RigidBodyDesc.kinematicPositionBased()` и коллайдер-капсула той же формы, что на экране: радиус `AVATAR_RADIUS`, общая высота 1,7 м. Помни, что `ColliderDesc.capsule(halfHeight, radius)` принимает **половину высоты цилиндрической части**, а не всей капсулы.
- [ ] `world.createCharacterController(offset)`, `offset` около 0,01 м. Настройки:
  - `setUp({ x: 0, y: 1, z: 0 })`;
  - `enableSnapToGround(0.1)` — не подпрыгивать на стыках;
  - `setMaxSlopeClimbAngle` — около 45°;
  - автостеп пока выключен, ступенек нет.
- [ ] Каждый подшаг:
  1. Горизонталь — как в M0-06: направление из клавиш, повёрнутое на `yawToRadians(frame.yaw)`, нормализованная диагональ, `WALK_SPEED * subDt`.
  2. Вертикаль — **гравитацию считаешь сам**: контроллер её не применяет. Храни `vy`, прибавляй `g * subDt`, сдвиг по вертикали `vy * subDt`.
  3. `controller.computeColliderMovement(collider, desired)`, затем `body.setNextKinematicTranslation(position + controller.computedMovement())`.
  4. `world.step()`.
  5. Если `controller.computedGrounded()` — `vy = 0`.
- [ ] `facing` — как в M0-06: поворачивается в сторону горизонтального движения, при нулевом вводе остаётся прежним.
- [ ] Ручной `clamp` по границам мира из M0-06 удаляется: теперь границы — это края берегов, и за ними аватар просто падает.

### 4. Падение и респаун

- [ ] Если аватар ниже `RESPAWN_Y` (например, −6 м: вода на −3,5), его тело переносится на точку старта (`setTranslation`, не `setNextKinematicTranslation`), `vy = 0`, `facing` — к провалу. Счётчик `respawns` увеличивается на 1.
- [ ] Точка старта — та же, что `createInitialState()` в M0-06: середина левого берега, лицом к провалу.

### 5. API `sim`

- [ ] `createSim(R: Rapier): Sim`. Порядок создания объектов всегда один и тот же: уровень, затем аватар. Это условие детерминизма (M1-01).

  ```ts
  interface Sim {
    /** Один тик: TICK_RATE раз в секунду, внутри PHYSICS_SUBSTEPS шагов Rapier. */
    step(frame: InputFrame): void;
    /** Простые числа для рендера и тестов; новый объект каждый тик. */
    state(): SimState;
    snapshot(): SimSnapshot;
    restore(snapshot: SimSnapshot): void;
    /** world.free(): WASM-память сборщик мусора не освобождает. */
    dispose(): void;
  }
  ```

- [ ] `SimState` дополняется полями:
  - `avatar.y`;
  - `avatar.grounded`;
  - `respawns` — счётчик респаунов, по нему рендер узнаёт о телепорте (шаг 6).
- [ ] **`SimSnapshot` = снимок Rapier + состояние игры вне Rapier:**
  - `{ physics: Uint8Array; tick; vy; facing; respawns }`;
  - всё, что влияет на следующий тик и не лежит в мире Rapier, должно быть в снимке, иначе откат в M2 разойдётся;
  - после `World.restoreSnapshot` character controller нужно **создать заново** с теми же настройками: его нет в снимке. Тело и коллайдер аватара находятся по сохранённым handle'ам, они переживают снимок.
- [ ] Константы: `TICK_RATE = 30`, `PHYSICS_SUBSTEPS = 2`, `world.timestep = 1 / (TICK_RATE * PHYSICS_SUBSTEPS)`, `GRAVITY = -9.81`, `RESPAWN_Y`.
- [ ] Старые `step(state, frame, dt)` и `createInitialState()` удаляются вместе со своими тестами. Поведение, которое они проверяли, переезжает в тесты `Sim` (шаг 7).

### 6. Клиент

- [ ] `mount` становится асинхронным: `const R = await loadPhysics()`.
  - Если после `await` `signal.aborted` — вернуть пустой unmount и **ничего не создавать**.
  - Если нет — `createSim(R)` и всё остальное как раньше.
- [ ] Цикл:
  - в `update`: `previous = current; sim.step(input.sample(tick, quantizeYaw(view.yaw))); current = sim.state();`
  - в `render`: интерполяция как раньше, плюс `y`.
- [ ] **Телепорт без интерполяции.** Если `current.respawns !== previous.respawns`, в этом кадре не интерполировать, а сразу поставить аватар и камеру в `current`. Иначе на один тик аватар «пролетит» из воды через полкарты к старту.
- [ ] Unmount: `sim.dispose()` — между `input.dispose()` и очисткой сцены. Порядок «обратный созданию» сохраняется.
- [ ] Временный `client/physics.ts` из спайка не возвращается: клиент берёт `loadPhysics` из `sim`.

### 7. Тесты

- [ ] Поведение из M0-06, на ровном берегу через `Sim`. Допуски задавай в миллиметрах: `offset` контроллера и прилипание к земле дают микросдвиги, бит-в-бит как раньше не будет.
  - нулевой ввод не двигает и не поворачивает;
  - `forward` при `yaw = 0` — вдоль −Z со скоростью `WALK_SPEED`;
  - диагональ не быстрее прямой;
  - `forward` + `back` гасятся;
  - при `yaw = π/2` «вперёд» — это −X;
  - аватар смотрит туда, куда идёт.
- [ ] Новое:
  - на старте аватар стоит на берегу: `grounded = true`, `y ≈ 0`, не проваливается за 5 секунд стояния;
  - пошёл в провал → упал → `respawns` стал 1, аватар на точке старта, `vy = 0`;
  - с внешнего края берега — то же самое.
- [ ] **Золотой хеш `Sim`:** записанная последовательность ввода (5 с к провалу, падение, респаун, 3 с вбок) → хеш `state()` + тик. Константа записывается на macOS, CI проверяет её на Linux. Это детерминизм уже нашей игры, а не только Rapier.
- [ ] **Снимок:** 2 с ходьбы → `snapshot()` → ещё 3 с с тем же вводом → хеш A; `restore()` → те же 3 с → хеш B; A = B. Отдельный кейс: снимок сделан во время падения, и `vy` восстанавливается.
- [ ] **Память:** 20 раз `createSim` → 60 тиков → `dispose()` без роста памяти WASM. Перехват `WebAssembly.instantiate` уже есть в `scenario.test.ts`: вынеси его в общий тестовый хелпер, а не копируй.
- [ ] `boundary.test.ts`: `sim/physics.ts` импортирует только Rapier, граница по-прежнему не пускает `three` и `@repo/game-core`.

### 8. Документы

- [ ] ARCHITECTURE.md, «Раскладка пакета игры»: коротко про форму `sim` — объект с `step` / `state` / `snapshot` / `restore` / `dispose`, снимок = Rapier + состояние игры. Пункт 3 решений M1 в README задач — со ссылкой на этот тикет.

## Критерии приёмки

- **Ощущения.** На берегу аватар ходит как в M0-06: та же скорость, плавно, без дрожания и подпрыгиваний. Камера ведёт себя как раньше.
- **Провал и края.** Шаг в провал или с внешнего края — падение и респаун на старте через 1–2 секунды. Камера переносится сразу, без «пролёта» через карту.
- **Тесты:** все из шага 7 зелёные, включая золотой хеш `Sim` в CI на Linux.
- **Загрузка** (замеры записать в PR):
  - «клик → первый кадр» на Slow 4G с предзагрузкой при наведении и без неё;
  - вес чанка игры (ожидаем ~1,75 МБ gzip).
- **Отмена во время загрузки:** DevTools → Network → Slow 4G, «Играть» и сразу «назад» до загрузки. В консоли нет ошибок, на странице нет `<canvas>`, повторный заход работает.
- **Критерии очистки из M0-05 и M0-06 на игре с физикой:**
  - один `<canvas>` в StrictMode;
  - 20 переходов без предупреждений WebGL;
  - лог памяти GPU: `geometries` → 0;
  - снятые слушатели окна.
- **Цена тика:** в dev залогируй среднее время `sim.step()` за 10 секунд. Ожидаем меньше 0,5 мс: два подшага по ~0,25 мс в M1-01 были при 50 досках, а здесь мир почти пустой.
- `bun run typecheck`, `bun run test`, `bun lint --max-warnings=0`, `bun fmt --check`, CI зелёный.

## Подсказки

- **Kinematic position-based тело двигает только `setNextKinematicTranslation`,** а применяется оно на следующем `world.step()`. Позицию для следующего подшага читай после `step`: `body.translation()`.
- **Контроллер смотрит на коллайдеры в их текущих позициях.** Если в одном подшаге звать `computeColliderMovement` после `world.step()`, он будет на шаг впереди. Порядок из шага 3 — compute, set next, step.
- **`computedGrounded()` — это «стоял ли на земле в этом расчёте».** Он знает о земле, только если в желаемом движении есть компонента вниз. Поэтому гравитацию в `desired` добавляй и тогда, когда аватар уже стоит: с прилипанием к земле это не даёт подпрыгиваний.
- **Не создавай `Vector` в каждом подшаге без нужды.** Объекты JS дешёвые, но `computedMovement()` возвращает новый объект на каждый вызов. Для 60 вызовов в секунду это не важно, а для 50 досок в M1-04 будет заметно. Пока хватит аккуратности, оптимизировать — в M1-08.
- **Respawn через `setTranslation`, а не `setNextKinematicTranslation`:** телепорт не должен «протаскивать» капсулу через мир и задевать берег по пути.
- **Хеш `Sim` бери из `state()`,** а не из снимка Rapier, по той же причине, что в M1-01: в снимке могут быть служебные данные. Используй тот же FNV-1a, что в `scenario.ts`, вынеси его в общий модуль.
- **Если хеш на Linux не совпал**, а в M1-01 совпадал, ищи источник недетерминизма в своём коде, а не в Rapier: `Math.random`, время, порядок обхода `Map` или `Set`, зависимость от того, когда пришёл ввод.
